# Win32Emu.Tools.NativeDllAnalyzer

A tool that analyzes native Windows DLLs from Windows ME to discover missing function implementations in Win32Emu.

## Purpose

This tool helps improve Win32Emu's compatibility by:
- **Extracting exported functions** from native Windows DLLs (from Windows ME)
- **Comparing exports** with Win32Emu's current API implementation status
- **Identifying gaps** in Win32Emu's API coverage
- **Generating reports** for documentation and prioritization

## How It Works

1. **Parse Native DLLs**: Uses PeNet library to extract exported function names from PE DLLs
2. **Load API Status**: Reads Win32Emu's API implementation status (generated by ApiStatusGenerator)
3. **Compare & Analyze**: Cross-references native exports with implemented functions
4. **Generate Report**: Creates detailed JSON report showing missing, stub, and implemented functions

## Usage

```bash
dotnet run --project Win32Emu.Tools.NativeDllAnalyzer <dll-directory> <api-status-json> [output-json]
```

### Arguments

- `dll-directory` - Directory containing native DLLs (e.g., `DLLs/WinME`)
- `api-status-json` - API status JSON file from ApiStatusGenerator
- `output-json` - Optional output file for the analysis report

### Examples

**Console output only:**
```bash
dotnet run --project Win32Emu.Tools.NativeDllAnalyzer DLLs/WinME docs/pages/api-status.json
```

**Generate JSON report:**
```bash
dotnet run --project Win32Emu.Tools.NativeDllAnalyzer DLLs/WinME docs/pages/api-status.json docs/pages/missing-functions.json
```

## Integration with GitHub Pages

The generated JSON report is consumed by the GitHub Pages site to display missing function information:

1. **Generate API Status** (from Win32Emu's source generators):
   ```bash
   dotnet run --project Win32Emu.Tools.ApiStatusGenerator docs/pages/api-status.json
   ```

2. **Analyze Native DLLs**:
   ```bash
   dotnet run --project Win32Emu.Tools.NativeDllAnalyzer DLLs/WinME docs/pages/api-status.json docs/pages/missing-functions.json
   ```

3. **Deploy to GitHub Pages**: The `docs/pages/` directory contains HTML/JS that reads these JSON files and displays interactive API coverage information.

## Report Fields

### Summary
- `totalDllsAnalyzed` - Number of native DLLs analyzed
- `totalNativeExports` - Total exported functions in native DLLs
- `totalImplemented` - Functions fully implemented in Win32Emu
- `totalStubs` - Functions with stub implementations
- `totalMissing` - Functions not present in Win32Emu
- `implementationPercentage` - Overall coverage percentage

### Per-DLL Analysis
- `nativeExports` - All functions exported by the native DLL
- `implementedFunctions` - Functions fully implemented (not stubs)
- `stubFunctions` - Functions with stub implementations
- `missingFunctions` - Functions not yet implemented
- `extraImplementations` - Functions in Win32Emu but not in native DLL (usually newer APIs)
- `coveragePercentage` - Implementation coverage for this DLL

## Use Cases

### 1. **Prioritize Implementation Work**
Identify which DLLs and functions are most critical to implement based on:
- Number of missing functions
- Coverage percentage
- Game/application requirements

### 2. **Track Progress**
Run periodically to measure implementation progress over time:
```bash
# Compare today vs. last month
diff missing-functions-2024-10.json missing-functions-2024-11.json
```

### 3. **Test-Driven Development**
Use native DLL exports as a test oracle:
1. Generate list of missing functions
2. Write tests for those functions
3. Implement functions to pass tests
4. Re-run analyzer to verify coverage

### 4. **Documentation**
Display missing functions on GitHub Pages so users can see:
- What's implemented vs. missing
- Which DLLs are well-supported
- Which functions to avoid (not implemented)

## Technical Details

### Dependencies
- **.NET 9.0** - Runtime
- **PeNet 4.0.3** - PE file parsing for exports
- **System.Text.Json** - JSON serialization

### PE Export Parsing
The tool uses PeNet to:
1. Load PE file headers
2. Parse export directory table
3. Extract function names and ordinals
4. Filter out ordinal-only exports (no name)

### Comparison Logic
For each native export:
1. Find matching Win32Emu module (by DLL name)
2. Locate function by name (case-insensitive)
3. Check `IsStub` flag from API status
4. Classify as: `implemented`, `stub`, or `missing`

### Limitations
- Only analyzes named exports (not ordinal-only exports)
- Doesn't validate function signatures (only names)
- Doesn't detect runtime-loaded DLLs (LoadLibrary)
- Based on Windows ME DLLs (older API set)

## Why Windows ME DLLs?

The `DLLs/WinME` directory contains Windows ME (Millennium Edition) system DLLs because:
- **Retrocomputing focus**: Win32Emu targets classic Windows games (Windows 95/98/ME era)
- **32-bit only**: Windows ME was the last consumer 32-bit-only Windows OS
- **Complete API surface**: Contains the core Win32 APIs used by games from that era
- **Reference implementation**: Provides ground truth for function signatures and behavior
